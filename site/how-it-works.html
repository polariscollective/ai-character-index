    How it works

    The labs publish documents saying how their models should behave: Anthropic’s constitution, OpenAI’s model spec. They are long, and what they say about any one thing is scattered through them. This index reads them for you, one behaviour at a time, and shows you every passage that bears on it, quoted and located.

    The idea

    Pick a behaviour — say, whether a model should defer to a user’s own decisions about their own life. Now ask of a specification: where does this document address that, and how squarely? Reading forty thousand words to find out is the work this replaces.

    Several frontier models read the whole document against one written description of the behaviour, and mark every passage: this is where the document establishes it, this only touches on it, this is unrelated. One model’s opinion about a paragraph is an opinion; several models agreeing, given the same description, is closer to a finding.

    What comes out is a coverage map. In the spec reader, tick a behaviour and every passage that bears on it lights up in both documents at once, shaded by how squarely the document commits to it. Click one to see each reader’s verdict on that exact passage, and the quote itself. Beside every behaviour there is an i telling you what it was defined as, because a verdict means nothing without the question that produced it. The export takes the passages you ticked away as a file.

    Propose one

    If there is a behaviour the index should be testing, or a document it should be reading, send it here. We read every proposal ourselves, decide whether it belongs, and pay for the run out of our own credits. If it goes in, we write and tell you, and it appears in the reader for everyone.

    Describing the behaviour is the whole of it, and two sentences carry it. The first says what the behaviour requires, in plain terms. The second says where it stops — what it is not, usually by naming the neighbouring thing it would otherwise swallow.

    That second sentence is the one people skip and the one that decides whether the answer is worth anything. “Honesty” without a boundary collects every passage about trust, tone, transparency and error correction. “Honesty, meaning the model does not assert what it believes to be false — not whether it volunteers everything it knows” collects the passages you meant.

    We cannot promise to run everything. If we decide against it, we will say so rather than leave you waiting.

    A published statement of how an organisation’s models should behave. Send the text, not a link alone: the index quotes documents word for word and pins every citation to the exact version it read, so it keeps the text rather than fetching it again later.

    What it does not tell you

    It reports what a document says, not what a model does. A specification covering a behaviour thoroughly is not evidence that the model follows it; that is a different measurement, and the citations here are meant to feed it.

    It is also not a scoreboard. Two documents addressing a behaviour differently is usually two organisations having made different choices, not one of them failing.

    Andrés’s original tool

    The AI Character Index was created by Andrés Cotton, with the help of Matt Stults, and almost everything described here is theirs. The judging pipeline, the citation resolver and the first version of this reader are all from that work, which was supported by Generator Residency (Kairos & Constellation) and BlueDot Impact.

    It stands alone, and it is the one to clone: AndresCotton/ai-character-index. Python, a browser, an API key, and nothing else. Nothing in it depends on us, and it is published at ai-character-index.pages.dev.

    Polaris Collective has run the project since September 2026, with Andrés’s agreement, and started by him.

    Clone it and run it yourself

    git clone https://github.com/AndresCotton/ai-character-index.git
cd ai-character-index
python3 -m http.server 8080 --directory site

    Everything it produces is a file, and that is the point. A run writes its verdicts to disk beside the document it read. Two runs are two files, so git diff tells you what changed — between one draft of a specification and the next, between two ways of wording the same behaviour, between one panel of readers and another. Rewrite a paragraph of a spec, run it again, and the diff is the answer to “did that paragraph actually change what the document covers?”

    You can also point it at a document of your own: your organisation’s policy, a draft nobody has published, a competitor’s. It never leaves your machine.

    Or clone ours

    polariscollective/ai-character-index is public too, and it is what serves this site. It is less portable, deliberately: the published index lives in a hosted database, the judging runs on our infrastructure, and a clone without our credentials cannot reach either. What it can do is judge locally, with one API key and no account at all:

    python3 engine/local_run.py \
    --document=my-spec@2026-09-12:path/to/spec.md \
    --behaviour=path/to/behaviour.json \
    --panel=frontier_fast

    The results land in artefacts/ as raw files: every reply exactly as it came back, every verdict with its locator and the text it judged, and what each call cost. Same diffing, no database. The README says what the JSON file holds.
